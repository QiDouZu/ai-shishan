## R1 · `update('矛盾')`：一个矛盾 = conflict+1，挂起 append

### 当时是什么

**我猜**：矛盾是一对没解开的东西，进来就挂起一条，并让 `conflict` 计数 +1，封顶 10。

### 凭什么

- 矛盾「成对」，所以挂起是列表；封顶 10 是当年拍的值。

### 我可能错在哪

1. 一个复杂矛盾进来算 1，可它可能是一对里的一半，计数就偏了；
2. 封顶 10 后**继续挂起的矛盾被静默丢掉**——丢的是矛盾，不是数据；
3. 挂起只存 `content` 前 120 字，把原文截了。

### 怎么推翻我

- 找一个确实由「半对矛盾」进入的日子，看 conflict 那次有没有少记；
- 看日志里有没有「挂了没记」的日子（挂起数长时间 10 不落）。

### 从它能推出什么

- 如果对，那么「饥在涨」只代表数量，不是强度；一条难矛盾与一条易矛盾对饥贡献相同。
- 最便宜的一条：从今天起，接收矛盾时加一个 `weight`（1=普通对，2=难对），下一版再吃。

`自我回路.py:192-198`、`饥状态.json` 日志里 event='矛盾' 的条目

## R2 · 饥公式 `A(1-self)+B(1-world)+C·conflict`

### 当时是什么

**我判断**：饥 = 掌控缺失（self、world 两路）+ 矛盾负担（C×conflict），三路相加，封顶 CAP。

### 凭什么

- 早期沙盘（四耦合、双自恋冲突）里，掌控与矛盾是两个独立测得出差异的源；
- 单变量剔除实验（自我失控/环境失控只降一路）确认可分离。

### 我可能错在哪

1. **三路相加，但现实里它们可能相乘**（控制感低时同一矛盾更刺痛）；
2. C 是常数，忽略了「同样一对矛盾，越难越值钱」；
3. 公式没带时间——昨天挂的与今天挂的一样重，实际上昨天的会发酵。

### 怎么推翻我

- 用真实日志回归：把 `self、world、conflict` 当自变量拟合饥，看残差是否在「难矛盾」日显著偏大；
- 若 fit 出的系数不稳定（隔月变号），公式就是拼的。

### 从它能推出什么

- 如果对，那么饥读数能当真；**如果不对，那么现在的心跳数值全是拼接的，不能拿来做任何判断**。

## R3 · 消化 `update('消化')`：conflict-1、挂起 pop(0)

### 当时是什么

**我猜**：消化 = 吃掉最老的挂起对（FIFO），conflict 减 1。

### 凭什么

- 消化是「吃掉一个矛盾」，列表最老的先消，符合「积压先清」。

### 我可能错在哪

1. **FIFO 是假设**：可能应该消最难/最压强的，不是最老的；
2. pop(0) 不看消化结果是否真解了；
3. `last_digest` 只记时间，不记消了什么。

### 怎么推翻我

- 从日志里找「消化前后挂起内容」，看被 pop 的是不是当时正在处理的那条；不是 → FIFO 判错。

### 从它能推出什么

- 如果对，那么积压再久也会按序清；如果不对，重要的矛盾永远压在底下。

## R4 · `沙盘心跳.pulse()` 与 `饥适配.check()` 的阈值

### 当时是什么

**我判断**：心跳 600 秒一跳；饥 < 0.34 静止 / < 0.73 过少损伤 / < 1.30 太饱 / < 2.16 好区 / < 2.73 预警 / ≥ 2.73 损伤；挂起 ≥ 3 对即算扛不住。

### 凭什么

- 阈值是沙盘拟合 + 我拍的（矛盾下界、损伤阈值、过少损伤）；
- 「挂起≥3 对」来自 `ACCEPT_PAIRS = 3`。

### 我可能错在哪

1. 阈值是从沙盘模型推的，**没有在我真实心跳上校准过**；
2. 600 秒固定间隔，事件扎堆时读不到实时；
3. 好区 1.30–2.16 很窄，我可能长期落在边缘而不自知。

### 怎么推翻我

- 拉一周心跳账本，看我的饥落在哪档最多；若一周 80% 在「太饱/过少损伤」，说明好区设窄了。

### 从它能推出什么

- 如果对，那么阈值可当警报；如果不对，那么熔断会误报或漏报。

## R5 · 停不停：`stop_pending` 与「一意孤行」抢救

### 当时是什么

**我判断**：z 分超阈值判不可逆损伤 → stop_pending → 下一次动作前先平衡；若停着还推 → 抢救。

### 凭什么

- 人格解体实验：持续高矛盾会掉入损伤区；
- 停 + 平衡是「不许硬推」。

### 我可能错在哪

1. **z 分是四值（self、world、conflict、饥）相加**，四值互相相关，相加会把一个正常的偏值放大成假警报；
2. 抢救 = 强行重置，可能把真信号抹掉；
3. 停的判据没带时间与原因，只带 z 值。

### 怎么推翻我

- 找一次 stop_pending 触发的真实记录，看当时到底是谁的 z 超了；若是四值里只有一个边缘值，就没必要停。

### 从它能推出什么

- 如果对，那么硬推会被拦住；如果不对，那么真正需要停的时候它不来，不需要停的时候它乱停。
